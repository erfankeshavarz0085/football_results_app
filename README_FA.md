# Shoot Ball

Shoot Ball یک اپلیکیشن Flutter برای نمایش نتایج فوتبال است که از سرویس‌هایی مانند SofaScore و FotMob الهام گرفته است. برنامه بازی‌های زنده و زمان‌بندی‌شده، اطلاعات لیگ، تیم، بازیکن و جزئیات مسابقه را در رابطی تیره و فوتبالی نمایش می‌دهد.

برای مستندات انگلیسی، [README.md](README.md) را ببینید.

## قابلیت‌ها

- نمایش بازی‌های Home بر اساس تاریخ، گروه‌بندی بر اساس لیگ، فیلتر داخلی و انتخاب‌گر تقویم
- صفحهٔ بازی‌های زنده با حالت‌های بارگذاری، خالی و دمو
- مرور لیگ‌ها و صفحهٔ لیگ با انتخاب فصل، بازی‌ها، جدول، آمار بازیکنان و تاریخچهٔ قهرمانان
- صفحهٔ تیم شامل اطلاعات باشگاه، بازی‌های اخیر، آخرین ترکیب و فهرست بازیکنان
- صفحهٔ مسابقه شامل خلاصه، رویدادها، آمار، ترکیب‌ها، ورزشگاه، داور و مسیر ورود به صفحهٔ تیم‌ها
- جست‌وجوی تیم، لیگ و بازیکن همراه با فیلتر کشور، تیم‌های محبوب و جست‌وجوهای اخیر
- صفحهٔ بازیکن شامل مشخصات، سابقهٔ باشگاهی، افتخارات و علاقه‌مندی
- ذخیرهٔ علاقه‌مندی‌های تیم، لیگ، بازیکن و بازی‌های دنبال‌شده
- نمایش تیم‌ها، لیگ‌ها و بازی‌های اخیراً دیده‌شده
- تنظیمات نمایش علاقه‌مندی در Home، موارد اخیر در Search، کنترل هشدار بازی و دادهٔ دمو
- محدودسازی درخواست API، تلاش مجدد برای خطاهای موقت، جلوگیری از درخواست تکراری، کش حافظه/دائمی و کش قدیمی هنگام خطا
- دادهٔ دمو برای ارائهٔ آفلاین یا اختلال سرویس API

## فناوری‌ها

- Flutter و Dart
- Provider

- بسته‌های `http`، `flutter_dotenv`، `shared_preferences`، `cached_network_image`، `intl` و `flutter_spinkit`

## ساختار پروژه

```text
lib/
  models/       مدل‌های دادهٔ API و رابط کاربری
  providers/    وضعیت برنامه و ذخیره‌سازی محلی
  screens/      صفحه‌های برنامه و تب‌های جزئیات لیگ
  services/     کلاینت API، تلاش مجدد، کش و منطق جایگزین
  utils/        تنظیمات، دادهٔ دمو و ابزارهای مشترک
  widgets/      اجزای قابل استفادهٔ مجدد رابط کاربری
```

## راه‌اندازی

1. Flutter SDK سازگار با Dart `^3.7.0` را نصب کنید.
2. وابستگی‌ها را دریافت کنید:

   ```bash
   flutter pub get
   ```

3. فایل `.env.example` را با نام `.env` کپی و مقادیر لازم را تنظیم کنید:

   ```env
   API_KEY=your_api_football_key_here
   API_ENABLED=false
   API_DEMO_FALLBACK_ENABLED=true
   API_REQUEST_INTERVAL_MS=250
   API_DEFAULT_SEASON=
   API_DEMO_FIXTURE_DATE=2024-07-14
   ```

فایل `.env` شامل اطلاعات حساس است و عمداً در Git نادیده گرفته می‌شود؛ هرگز کلید API را commit نکنید.

## تنظیمات محیطی

| متغیر | کاربرد |
| --- | --- |
| `API_KEY` | کلید API-Football؛ فقط برای درخواست واقعی لازم است. |
| `API_ENABLED` | فعال/غیرفعال‌کردن درخواست واقعی API. |
| `API_DEMO_FALLBACK_ENABLED` | امکان استفاده از دمو را فراهم می‌کند؛ کلید درون برنامه تعیین می‌کند که استفاده شود یا نه. |
| `API_REQUEST_INTERVAL_MS` | حداقل فاصلهٔ درخواست‌ها؛ مقدار پیش‌فرض `250` میلی‌ثانیه است. |
| `API_DEFAULT_SEASON` | سال شروع فصل اختیاری؛ خالی باشد، تغییر خودکار در تیر/ژوئیه انجام می‌شود. |
| `API_DEMO_FIXTURE_DATE` | تاریخ اختیاری مورد استفادهٔ دادهٔ دمو. |

برای اجرای دمو/آفلاین، `API_ENABLED=false` و `API_DEMO_FALLBACK_ENABLED=true` را تنظیم کنید و سپس **Demo fallback** را در Settings فعال کنید. برای دادهٔ واقعی، یک کلید معتبر و `API_ENABLED=true` لازم است.

## رفتار داده و کش

برای درخواست‌های دارای کشِ بازی‌ها و جدول‌ها، برنامه این ترتیب را دنبال می‌کند:

1. کش تازهٔ حافظه
2. کش تازهٔ دائمی در `shared_preferences`
3. درخواست به API-Football
4. کش قدیمی حافظه یا دائمی در صورت خطای درخواست
5. دادهٔ دمو در صورت فعال‌بودن جایگزین دمو

بعضی endpointها، فصل‌ها و داده‌های تاریخی API-Football به پلن API وابسته‌اند. داده‌های دمو عمداً کم‌حجم و مناسب ارائه هستند و جایگزین دادهٔ واقعی محصول نیستند.
